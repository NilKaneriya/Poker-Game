# Load test ramp: 400, 800 and 1,500 tables (2026-11-23)

Three runs of `qa/load-test/load-test.js`, each 60 s of play, to find where a single server
instance stops coping. Follows the 200-table run in
[2026-11-23-200t-60s.md](2026-11-23-200t-60s.md).

## Setup
| | |
|---|---|
| Server | throwaway server started by the test (own port, JSON storage in a temp folder, real data untouched) |
| Layout | one human per table plus 5 bots, 6 seats per table |
| Duration | 60 s of play after everyone joined, per run |
| Timings | BOT_THINK_MS=150, NEXT_HAND_DELAY_MS=300, RESULT_SHOW_MS=300 (about 10x faster than real play) |
| Machine | the same laptop runs the server and all simulated clients (see the 200-table report for specs: Ryzen 7, 12 threads, 15 GB) |
| Commands | `npm run load-test -- --tables=400 --seconds=60`, same with `--tables=800` and `--tables=1500` |

## What it shows
- **Up to 400 players: healthy.** Replies stayed under 50 ms at p99.
- **Around 800 players: degraded.** Median reply 181 ms, p99 608 ms. Hands per minute went down
  compared with 400, so the server is saturated. Node runs all game logic on one CPU thread.
- **At 1,500 players: overloaded.** Median reply about 5 s, joining took 393 s, 1,277 actions
  were rejected. They are probably actions that arrived after the table had moved on, but this
  was not investigated.
- **No crash and no dropped connection at any size.** The server slows down instead of failing.

## Caveats
- The simulated clients share the machine with the server, so part of the slowdown at 800 and
  1,500 is the test client using CPU. The real server limit is probably somewhat higher.
- Bots and players act about 10x faster than in real play, so each simulated player is much
  busier than a real one.
- JSON storage only. MongoDB was not part of these runs.
- Time to connect was not captured for the 400 and 800 runs.
- Numbers come from a single run each, not an average of several.

## How to scale past this
Run several server instances behind a load balancer, with the Socket.IO Redis adapter for
cross-instance events and MongoDB as the shared store.
